# 引き継ぎ書 (brief) の書き方

`oracmux.py` が組み立てる brief の骨格 (読者・語り手の行→論点→経緯→制約→出力契約→添付一覧→添付本文)。
母艦が用意するのは **問い・経緯・制約・添付の選定**。oracle の tips と同じで、6〜30 文の説明を付けた問いほど答えが良い。

```
# oracmux brief — <slug>
読者＝<engine>／語り手＝弊社の作業エージェント／相手＝<engine>／その先＝宮崎さん (裁定者)

## 論点 (問い)        ← 1 つに絞る。判断なら「A か B か、決め手は何か」の形
## 経緯・文脈         ← プロジェクト・環境・版・これまでに試したこと・なぜ今それが要るか
## 制約               ← 変えられないもの (期限・既存仕様・禁止事項)
## 出力契約           ← 既定: 結論先行・根拠→結論・根拠なき断定禁止・【要確認】明記・日本語
## 添付一覧           ← 展開した/しなかった (理由つき) ファイルの全数
## 添付ファイル本文   ← ### FILE: <path> (<bytes>) + フェンス (JSON は 1 行に圧縮)
```

## 書くときの基準

- **問いは 1 本**。複数あるなら council でも ask でも別 run にする (回答が混ざると裁定できない)
- **経緯は「相手が何も知らない」前提**で書く。リポ名・OS・ツール名・版・失敗した試行と観測結果を具体値で
- **添付はそのまま展開される**。生 transcript・巨大ログ・画像 PDF は入れない (60,000 字の枠を食うだけ)。
  必要な箇所だけ切り出したファイルを作って `--file` する
- **社外秘・NDA 素材は入れない** (ガードは補助であって判断の代わりではない)。クライアント名が要らなければ伏せる
- **出力契約は変えてよい**: 比較表が欲しい (`--output-contract "表で。列は ..."`)、英語で返してほしい、字数上限、など
- **語り手を変えて写す**: 先方資料や自分の過去投稿を貼るときは「お渡し→受領・御社→弊社」に直してから

## 例 (`--question-file Q.md` の中身)

```
mycmux (Tauri v2 + React 19・Windows) の Web ペイン (WebView2 child webview・push 専用) に
読み戻し API を足すなら、A) Rust 側で webview.eval + oneshot 返信 (push と同型) と
B) --remote-debugging-port を開けて外部から CDP、のどちらが妥当か。決め手と落とし穴を挙げてほしい。
```
`--context-file` に ADR 0008 と要件書の該当節、`--file` に `webpane.rs` を渡す。
