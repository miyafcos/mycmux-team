# スマホにターミナルを載せ続け、その代わり転送層を作り直す

Status: accepted (2026-08-17)

承認するだけなら質問カードと直近の出力で足りるため、端末表示を捨てれば描画エンジン (284KB) ごと削れて軽くなる。それでも端末は常時載せる判断をした (2026-08-17 宮崎さん裁定)。何に対して答えているのかを実物で確かめられることを優先する。

この判断の帰結として、**転送層の作り直しは任意ではなく必須になる**。今の遅さ・不安定さは端末をライブで流していることに由来しており、端末を残す以上そこを直さない限り体験は変わらない。具体的には、出力のバッチング (remote だけデスクトップ向けの合流処理の外にある)、受信位置からの差分再開 (毎回最大256KBを再送している)、フロー制御時に取りこぼしを黙って捨てない仕組み、再接続時に画面を二重描画しない処理、既定を「見るだけモード」にして PC 側の画面幅をスマホが書き換えないこと、描画エンジンの更新が対象になる。

## 検討した選択肢

- **端末を載せない (質問カード + 直近出力のみ)**: 最も軽く、崩れる余地がない。却下理由は、込み入った対話画面を再現できず、何に答えているのか確かめられない場面が残るため。
- **必要なときだけ遅延読み込み**: 普段は軽い。却下理由は、二重の作りになるうえ、端末を開いた瞬間に同じ問題が戻るため。
