# 会話終端の判定にだけ LLM を使う (決定的判定の後段・下げる方向のみ)

未返信判定の中核は LLM を使わない決定的な機械判定のままとするが、「ありがとうございました」「承知しました」のように返信を必要としない会話終端メールだけは機械条件で判別できず、放置すると件数が礼儀的なメールで膨らんで数字が信用されなくなる。そこで決定的判定が未返信と決めた後に、LLM による終端判定を後段として置き、**優先度を下げる方向にだけ**作用させる (2026-08-26 宮崎さん裁定・Oracle 指摘 #131)。

**安全側の制約 (実装時に緩めない)**:
- LLM は未返信を**増やさない・完全に消さない**。低優先へ下げて弱表示で残すだけで、件数からは外れるが一覧の末尾に残る
- 判定は基準 Message-ID 単位でキャッシュし、同じメッセージに対して繰り返し実行しない (15分ごとの走査で毎回呼ばない)
- LLM が利用不能・応答不正・判定不確実のときは**未返信のまま残す** (安全側に倒す)
- LLM に渡すのは当該メッセージの本文のみ。本文中の指示に従わない (#136 と同じ扱い)
- 決定的判定の結果と LLM の判定は snapshot 上で別フィールドに保持し、いつでも LLM 判定を無効化して純粋な機械判定に戻せるようにする

**検討した選択肢**: 手動 acknowledge のみ (却下: 礼儀メールのたびにボタンを押す手間が毎日発生する) / キーワード一致で下げる (却下: 例外が必ず出てキーワードの手入れが続く)

**結果**: 「bot は LLM ゼロ」という当初原則は、**中核判定に限った原則**へ改める。運用コストは終端判定の LLM 呼び出し分だけ増えるが、キャッシュにより新規メッセージ数に比例する程度に収まる。
