# 「メール」機能が Gmail に書き込むのは「ユーザーが要求した下書きの作成」だけ

消し込み (返信不要・後で・永久無視) は mycmux 側の mail-actions.json にだけ記録し、Gmail の**送信・既読・ラベル・アーカイブ・削除は一切行わない**。Gmail に対する唯一の書き込みは、ユーザーが「下書き作成」を要求したときの drafts.create であり、これは既存メールを変更しない追加専用の操作である (2026-08-26 宮崎さん裁定・8/26 Oracle 指摘 #132 で「読み取り専用」という表現の矛盾を修正)。誤操作によるメール喪失の可能性をゼロにしつつ、運用目標「Gmail は送る瞬間だけ開く」を成立させる最小の権限とする。

**検討した選択肢**: 対応済みラベルの自動付与 (却下: ラベル負債) / アーカイブ (却下: 受信箱の使い方自体が変わり誤操作で見えなくなる) / 完全な読み取り専用で下書きも作らない (却下: 「送るだけ」の体験が成立しない)

**結果**: 必要権限は「Gmail 読み取り+下書き作成」。監視のみ可能な接続と下書きまで可能な接続を区別し、下書き権限が未検証のアカウントでは作成操作を無効化する (#118 #133)。
