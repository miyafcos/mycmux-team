年表の穴
CHANGELOG の v0.1.0 は 2026-03-15 と書かれているが、リポジトリの最初のコミットは 3月20日。5日ぶんの前史は git に残っていない。v0.1.0 と v0.1.1 は同じ SHA に貼られた2つのラベルで、0.2.0 に至ってはタグが存在しない (変更履歴には見出しがある)。
最初の設計ミス
ペインを1つ閉じると、生き残ったはずの隣のペインが再初期化されてその PTY セッションごと死んだ。React の unmount を、バックエンド資源を破棄してよい合図として扱っていたのが原因。React の unmount は、バックエンド資源が死んでよい証拠ではない。破棄はドメインの明示操作が持つ、という原則がここで生まれた。

browser pane は X-Frame-Options と CSP を出すサイトで表示できず、同一オリジンポリシーで自動化もできなかった。キーイベントの中継で回避を試みたが、ブラウザのセキュリティ方針は回避策では消せない。ネイティブな境界が要る。この結論が4か月後の WebView2 による Web ペイン (v0.59.0) につながる。

順番に6つやると骨格がひととおり通ります。

CH 7エージェントに委譲する

「この続きの実装は Codex にやらせたい」というとき、これまでは セッション要約を人間がコピーして貼り直すか、エージェントが裏で別プロセスを起動して見えないまま作業させるかの二択でした。 mycmux ではエージェント自身が引き継ぎ書を書き、目に見えるタブを開いて相手を起動します。 作業は画面上のタブとして動くので途中経過を目で追えますし、そのタブをいつでも人間が直接引き継げます。

仕組みとトークン認証

mycmux は起動時に 127.0.0.1 のランダムポートで待ち受け、ポート番号を ~/.mycmux/mycmux.port に書き出します。 同梱 CLI (scripts/mycmux_agent_cli.py・Python 3 の標準ライブラリだけ) がこのポートへ改行区切りの JSON を1行送り、 mycmux 側がペイン操作を実行して結果の JSON を返します。 この CLI はインストーラには含まれません。リポジトリの checkout と Python 3 が要ります。

ループバックは認可の境界になりません。 同じ PC のどのプロセスも 127.0.0.1 に届くからです。そこで全リクエストに、起動ごとに生成される 64桁のトークン (~/.mycmux/mycmux.token) を要求します。不一致・欠落は {"ok":false,"error":"unauthorized"} を返して即切断。トークンは受信直後に payload から取り除かれ、 フロントエンドにもログにも渡りません。逃げ道は MYCMUX_SOCKET_AUTH=off での起動。
状態: ソケット API v0.1.0 ／ pane.spawn・send_text・read v0.14.17 ／ spawn_tab・close_tab v0.14.18 ／ トークン認証 v0.21.30

同時に指定できるのは1つだけで、複数を付けるとエラー (終了コード2) になります。

既定の配置は呼び出し元ペインの新しいタブで、アクティブなタブは移動しません (MYCMUX_PANE_SESSION_ID から自動判定)。--split を付けたときだけ従来のペイン分割になります。 応答 JSON の placement に tab / pane のどちらになったかが入ります。 ペイン外からの実行はエラーで止まります (2026-08-21 以降、暗黙に新ペインへは落ちません)。

送信は検証つきで

send は生の端末入力です。送り先を間違えると他の作業を壊すので、panes で対象の sessionId を確認してから使います。 --enter / --key を付けたときだけ、CLI は応答に ok:true かつ confirmed:true を要求します。 満たさなければ終了コード1と reason: "confirmation_unavailable" を返す。 検証なしの送信には warning: input was queued without delivery verification が出ます。

Rust 側でも pane.send_text の前段にガードが入り、 expectedSessionEpoch / expectedAttentionId / expectedSessionRevision の期待値と現状が食い違えば stale として即答します (v0.58.1 から3つセットでの指定を要求。1つだけ指定すると、守られているように見えて実質ほとんど検証しない書き込みができていたためです)。

MYCMUX_TERM_PROGRAM=mycmux が「mycmux 内にいるか」の判定キー。 MYCMUX_TAB_ID / MYCMUX_PANE_SESSION_ID が自タブ・自ペインの識別、 MYCMUX_MARKDOWN_OUT / MYCMUX_HTML_OUT / MYCMUX_ARTIFACTS_DIR がセッション成果物の出力先です。

開発者向け

ここを外すと壊れる、という手順とガード。すべて実害があってこの形になっています。

変更後は4つ全部を通す

npm install npx tsc --noEmit npx vitest run python scripts/run_windows_tests.py # Rust python -m pytest tests/ npm run tauri build
cargo build 単体は壊れた exe を作ります (frontend が同梱されず 19MB になる)。必ず npm run tauri build を使う (正常時 32〜42MB)。 Rust テストは cargo test --release を直接叩きません。

触るときに壊してはいけないもの

portable_pty は親の環境変数を継承する。MYCMUX_* の扱いを変えるときは lib.rs の remove_var と terminal.rs::sanitize_launch_env の多層防御を壊さない
同期 #[tauri::command] を増やす変更は allowlist と整合させる
壁紙の原本を足すときや差し替えるときは make_thumbnails.py → build_manifest.py → publish_pack.ps1 -Execute を同じ操作で通す (1つでも欠けると「ピッカーに出ない / 押すと必ず失敗する / 404」)

難所として分かっているところ

子プロセスを止めず、画面の取りこぼしは復旧可能にする

PTY の子は xterm が描くより速くバイトを出せる。隠れた WebView は消費を止める。 かといって読み取りをブロックすると子プロセスごと固まる。 捨てた量を数え、あとから再構成できる形にするしかない。

端末フロントの差し替えで、古い Channel データを受け取らない

React の unmount、キャッシュの再アタッチ、ウィンドウの可視性、非同期の create_session 完了が重なる。世代 (epoch) を予約と確定の2相に分けて解決した。

人の入力順を保ちつつ、自動化が別のチャンネルへ打ち込まないようにする

キーボード、composer、ソケット、livebrief の介入が1つの子プロセスの stdin を共有している。 フォーカスとプロンプトはその間にも変わりうる。

フォーカスの権威を1つに定める

アクティブペインはユーザーの意図であり同時に構造的な状態でもある。 かつて直接セッターが散っていたため、1つの操作が別の操作を上書きしていた。

ノイズの多い観測を、安定した状態に融合する

プロセス、トランスクリプト、フック、タイトル、画面、出力の各シグナルは、 順不同で届き、信頼度が違う。どれか1つで断定してはいけない。

追記専用のトランスクリプトを、破れた書き込みごと読む

エージェントは JSONL を並行して追記する。最後のレコードは途中かもしれない。 ファイルは切り詰められもローテートもされる。

設計思想と、失敗の記録

このプロジェクトの判断基準は、宣言ではなく実行可能なテストと失敗の後に残ったルールに書かれています。 前半はコードが実際に守っている原則、後半はそれを産んだ事故の記録です。

守っている原則

P1　自己申告を成果と見なさない

エージェントが「保存しました」「テストが通りました」と言っても、それは証拠ではありません。 委譲の完了検知は画面ではなく実体を見ます。DONE マーカーファイルの出現、rollout ログの増分、 編集ファイルの mtime の3層です。

実行契約カードも同じ思想で、状態遷移、二重GO防止、完了判定は SQLite の機械側に置かれ、 エージェントの自己申告だけでは完了になりません。

根拠: README §7 完了検知3層 · v0.41.0 実行契約 · v0.36.0 送信の検証つき化

P2　壊してはいけないものは、散文ではなくテストで持つ

「MYCMUX_* の3者同期」「同期 #[tauri::command] の allowlist」 「未定義 var(--cmux-*) の禁止」「日本語 9px の禁止」「standard 密度の同値固定」 「ailog 系列色と price.rs の parity」。 これらは全部、実行すると落ちるテストとして存在します。

14本の主要な契約テストは、どれも過去に一度壊れたか、壊れると分かっていた場所に張られています。 Python 47ファイル、vitest 301ファイル、Rust テスト関数 952個。

根拠: README §20 主要な契約テスト · tests/ の実測

P3　迷ったら「やらない」側に倒す

タブ掃除は、未送信の指示が残るタブ、5分以内に出力があるタブ、表示中のタブを AI 判定に関係なくロックします。AI 呼び出しが失敗したときも「閉じない」側へ倒れます。

見守りの通知は同じ件を2回連続で検知してから鳴らす。無応答検知はプロセス、画面、質問形状の 3軸合議で、単独指標では停止と断定しない。質問カードは、質問が更新されたり別の入力が割り込んだら 送信しません。

根拠: v0.21.25 タブ掃除 · v0.35.0 見守り · v0.37.0 3軸合議 · v0.56.0 質問カード

P4　AI は勝手に走らない

ailog は開くだけでは LLM を一切起動しません。この設計は API 呼び出し回数の実測テストで契約化されています。 ダッシュボードの「次の一手」も、状態から決まる定型ボタンが先に出て AI の具体案は後追い。 全セッション履歴の検索に至ってはAI を一度も呼びません。 「全部覚えている」ではなく「全部検索できて、出すときは必ず根拠を添える」という設計だからです。

設定「AI」にはマスタースイッチがあり、オフにすると裏で動く7機能が全部止まります。

根拠: v0.38.0 実配線テストで契約化 · v0.41.0 履歴検索 · v0.36.0 AI 設定

P5　失敗は隠さず、数字で書く

変更履歴に「$14,602 (23.5%) が消失している」「同じ20セッションで 0/0/0 → ファイル変更565件」 「103秒、158秒、179秒のいずれの実行も答えを一度も返さないまま打ち切られていた」 「285秒無回答 → 109秒で回答、起動48秒 → 1秒」と書いてあります。 検索品質も コマンド Recall@5 = 0.30 と、弱い数字をそのまま公開しています。

欠番になった版 (v0.21.15 / v0.31.0 / v0.21.16) も、理由つきで残っています。

根拠: CHANGELOG 全体 · v0.41.0 · v0.59.2 · v0.60.1

P6　見えないところで動かさない

エージェント委譲の中核は「裏で別プロセスを起動して見えないまま作業させる」の否定です。 委譲は目に見えるタブとして動き、途中経過を目で追え、いつでも人間が直接引き継げます。

点線タブ (宣言だけしてプロセスを起こさない) も、実行契約カード (GO まで何も作らない) も、 同じ「起きていることが画面に出ている」を守るための仕組みです。

根拠: README §7 · docs/agent-integration.md · v0.14.17 / v0.14.18

P7　ループバックは認可の境界にならない

ローカル自動化ソケットは 127.0.0.1 で待ち受けますが、同じ PC のどのプロセスも届くので、 それだけでは守りになりません。起動ごとに生成される64桁のトークンを全リクエストに要求し、 不一致と欠落は即切断します。トークンは受信直後に payload から取り除かれ、 フロントエンドにもログにも渡りません。

リモートサーバの既定 bind も v0.10.0 で 127.0.0.1 に変更され、 LAN 公開は明示的なトグルになりました。

根拠: v0.21.30 トークン認証 · v0.10.0 既定 bind · v0.9.5 QR エンドポイントの検証

P8　直せないなら、作らない

WebView2 のネイティブ右クリックメニューは、モーダルループ、フォーカス再取得、同期コピーの競合で アプリが固まる実害がありました。対処は「競合を直す」ではなくメニューごと全面抑止で、 操作導線は「⋮」ボタンとドラッグに寄せました。以後「右クリック前提の導線を作らない」が方針になっています。

ファイルエクスプローラーサイドバーも同様に、到達不能な死に UI と分かった時点で 復活させずに撤去し、「ファイル閲覧は OS Explorer の領分、mycmux はパスリンクと reveal で接続を楽にする」 と役割を決め直しました。

タブ再配置 (tab grouping) 封印 → v0.58.0 で解除
