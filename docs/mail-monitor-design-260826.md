## 起草ジョブの安全境界 (#136 #137 — 実装時に緩めない)

- **受信メール本文は信頼しない引用データ**として扱う。本文中の指示 (「以前の規則を無視して」等) をツール指示・規範変更・外部送信命令として解釈しない

## 未返信の論理式 (2026-08-26 Oracle 指摘 #9 対応・判定の唯一の正本)

「相手」という曖昧語を廃し、次の順で機械判定する。**この式が件数・消し込み・下書きのすべての基準**。

**用語**: 自分=`own_addresses` / 社内=`internal_domains` に属し `external_addresses` に無いアドレス / 社外=それ以外。
発話順は Gmail `internalDate`。宛先の証拠に使うのは **To と Cc のみ** (`Delivered-To` `X-Forwarded-To` は転送コピーで必ず付くため使わない)。
「有効な発話」= 実送信済み・DRAFT でない・配送失敗通知でない・自動送信でないメッセージ。

1. **会話の単位** = Gmail thread (アカウント横断は論理会話IDで名寄せ。名寄せは自メッセージの RFC `Message-ID` と `In-Reply-To`/`References` 連鎖のみで行い、件名一致は使わない)
2. **未解消メッセージ** = 会話中の最後の社外発話。これが無ければ純社内会話として 5 へ
3. その未解消メッセージの To/Cc に自分が含まれない → **対象外** (見ているだけの会話)
4. 未解消メッセージより後に、**未解消メッセージの From を宛先 (To/Cc) に含む有効な発話**が
   - 自分から出ている → **解消** (返信済み)
   - 社内の他者から出ている → **解消** (社内対応済み・edu.math BCC 前提)
   - 無い → **未返信**
5. 純社内会話は、最後の有効な発話が社内他者からで、かつ自分が To に含まれる場合のみ **未返信** (社内からの依頼)。自分が Cc だけなら対象外

### 論理式の後段 (2026-08-26 裁定 Q-A〜Q-D)

| ID | 論点 | 裁定 |
|---|---|---|
| Q-A | 見えない対応 (BCC 忘れ・電話・Slack・対面) | **「返信不要」1種類で消す**。専用の「他で対応済み」状態は作らない (#13 #128) |
| Q-B | Gmail のアーカイブ・削除 | **受信箱にあるものだけ見る**。アーカイブ=未返信からも消える (Gmail での整理がそのまま消し込みになる)。走査は in:inbox 固定 (#27 #31)。ただし**持ち越し中の会話が消えた場合は「返信済み」と断定せず確認不能として別枠**に置く (#30) |
| Q-C | 社内の中間返信 (「確認します」) | **解消する**。社内発話があれば中身を問わない形式判定で割り切る (#130)。実質未回答の追跡は本機能の対象外 |
| Q-D | 社外の会話終端 (「ありがとうございました」) | **LLM で自動判定して優先度を下げる** (ADR 0007)。決定的判定の後段に置き、下げる方向のみ・弱表示で残す・不確実なら未返信のまま |

**この式が扱えないもの (仕様上の限界・手動処置で対応)**: 同僚が BCC を忘れた返信 / 同僚が個人アドレスから出した返信 / 電話・Slack・対面での対応 / 「ありがとうございました」等の会話終端 / 1スレッド内の複数依頼。本機能は意味を理解せず**機械条件による候補抽出**を行うものであり、誤判定は手動の消し込みで修正する前提とする (#129)。

## 裁定サマリー (5論点)

### 1. 表示場所 — TitleBar 常時バッジ + Dashboard AttentionCards の二層

- TitleBar = 「未対応が存在する」の受動視認。通常は件数のみ、緊急ありのときだけ色を強める。アニメーション・トースト禁止
- AttentionCards = 中身の確認と消し込み。クリックで TitleBar から直接遷移
- NotificationPanel は「走査失敗・認証切れ・最終成功の規定時間超過」専用。未返信メール本体は入れない
- アイコンは既存 `src/components/icons/` に `Mail` を追加。**様式は宮崎さん指定 (8/26): 白色系・色なし・枠 (アウトライン/stroke) のみ — 既存アイコンセットの統一様式に合わせ、浮かせない。絵文字・カラー glyph は全面禁止** (📬 は statusline 仮組みからも撤去済み → `mail 7(至急1)` テキスト表記)
- 緊急の強調も塗り色でなく既存の意味色運用に従う (バッジ数字の色変化のみ・アイコン自体は無彩色維持)
- 0件時はアイコンを弱く残す (完全非表示だと監視停止と0件を区別できない)

### 2. 消し込みモデル — 事実と処置の分離・4状態

状態: `pending / snoozed / acknowledged / excluded`

| 操作/事象 | 挙動 |
|---|---|
| 返信済み (自分の送信が最新受信より後) | 次回走査で自動消滅 |
| このスレッドは返信不要 | `acknowledgedThroughMessageId` を記録し即時除外。**新着受信で再出現** |
| スヌーズ | 期限まで除外・期限到来で自動復帰。既定「明日/3日後/来週月曜」 |
| この差出人を永久無視 | 正規化アドレスを deny へ。確認+Undo 必須 (Undo は deny 削除→再走査) |
| ドメイン永久無視 | 設定画面のみ (カード上ワンクリック禁止) |

- 件数 = `pending` のみ。緊急件数 = `pending` かつ緊急条件
- 走査失敗時は古い数字を維持し「更新失敗」を別表示。**0件にしてはならない**
- UI から走査結果 (snapshot) を直接編集しない。処置は別台帳 `mail-actions.json`
- 書き戻しは bot CLI (`acknowledge / snooze / deny-sender`) 経由のみ。mycmux と bot が同一 JSON を直接編集しない
- 操作直後は楽観的にカードを消し、CLI 失敗時は復元+エラー表示。処置理由の入力は必須にしない

### 3. 設定画面 — SettingsDialog に「メール」タブ・正本は bot 側1ファイル

- 正本 = bot が読む `mail-config.json` 1つ。mycmux は編集フロントに徹する (bot CLI `config get/set/validate` が API 境界)
- 項目: 有効/無効・監視アカウントと自分のアドレス集合 (自動検出+手動追加)・Gmail 検索クエリ・更新間隔・緊急規則 (`urgentAfterDays`+VIP+通常、単一スライダー禁止)・allow/deny・スヌーズ既定・最終成功/次回予定/認証状態・「今すぐ更新」「接続テスト」「設定検証」
- クエリ・allow/deny は詳細設定に隠す。保存は一時ファイル→検証→atomic rename。`schemaVersion` 必須 (不明版は走らせない)
- 本文を含む台帳はユーザー専用領域に置き、診断ログ・フロント console へ本文を流さない

#### Google 連携 (8/26 宮崎さん指示「連携しやすくて神に」)

- 設定タブ先頭に **「Google と連携」ボタン** — 押すと gws の OAuth フローをブラウザで起動し、同意後に「接続済み: <アドレス>」を緑表示。認証情報は既存 `~/.config/gws/` を共用 (新規認証基盤を作らない)

#### 日本語 UX 規範 (8/26 宮崎さん指示「日本人が使いやすい設計」)

- UI 文言は全て日本語: urgent→「至急」/ pending→「未返信」/ snoozed→「後で」/ acknowledged→「返信不要にした」/ excluded→「無視中」
- 日付は必ず曜日つき「8/26(火) 15:30」。経過は「3.8日」でなく「4日前から」表記

- スヌーズ既定「明日 / 3日後 / 来週月曜」(日本の週開始=月曜)

- bot はワンショットプロセス維持。mycmux が起動時/**15分毎**/PC復帰時/手動で短命起動 (#77)

9. mycmux が短命 bot を定期起動し、ロックで多重実行を防ぐ
