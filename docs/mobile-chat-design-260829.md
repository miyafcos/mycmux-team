# ポケットmycmux — 要件定義書 v1.0

作成: 2026-08-29 (宮崎さん発話の要件起こし → グリル6問で確定)
状態: 要件確定 — 宮崎さんの最終OK待ち。実装着手は別途指示 (構想承認≠実装GO)

## 一言でいうと

iPhone のホーム画面から1タップで開く、LINE / Telegram 型のチャットアプリ (PWA)。中身は ①mycmux の全セッション管制 ②未返信メールの返信一本道 ③PC上ファイルの閲覧。Tailscale (tailnet 内限定) で配信し、トークン入力なし。**mycmux Remote (7683) と mulmoclaude (7684) を置き換える。**

## 経緯

2026-08-29 宮崎さん発話:
- mycmux Remote はトークン入力が面倒。mulmoclaude は多数セッションを見る仕組みになっておらず iPhone の見た目に合っていない。両方廃止してよい
- LINE / Telegram のようなチャットアプリ形式が最適。「チャットアプリの入力の入り口の形式が一番合っている」
- 実装は「Tailscale で HTML で再現できるところから」
- メールも同じ場所で: 未返信が見やすく並び、1行 (「よろー」) 入れてポチ → Claude が宮崎さんの文体で起草 → Gmail 下書きまで一直線

## 確定要件 (R列)

| ID | 要件 | 確定根拠 |
|----|------|---------|
| R1 | 認証: トークン入力なし。tailnet 接続自体を認証とする。Funnel (インターネット公開) 禁止 | 発話 |
| R2 | 表示対象は **mycmux 管理下のセッションのみ** (cron・単発起動は対象外) | グリルQ1 |
| R3 | トップ画面は**グループ一覧** (🖥 mycmux / ✉ メール / 📄 レポート棚)。mycmux タップでタブ一覧へ | グリルQ2 |
| R4 | タブ一覧の各行 = 最前面ペイン名 + 最後の発話スニペット + タブ内ペイン数 + 状態 (稼働/待機/要対応)。チャットアプリのトーク一覧のように縦に並べる | 発話 |
| R5 | ペイン詳細 = ダッシュボード E2 型の型付きタイムライン (生ターミナルではない)。長文は折りたたみ | 発話 |
| R6 | コンポーザ (入力欄) は常設。**idle ペインへは即送信・稼働中ペインへは「予約投函」** — PC 側が idle 化を待って自動投函。送達確認は画面 read で入力欄 `❯` の残存チェック (agentStatus では判定しない) | グリルQ3 + feedback_mycmux_send_verify_by_screen |
| R7 | パスリンクはタップで閲覧: HTML 直配信 / MD レンダ / docx は PDF 変換。許可範囲 = **C:\Users\miyaz 配下 + G:/マイドライブ 配下**。拒否リスト = .env / credentials* / tokens / 秘密鍵 / .ssh (パターン封鎖・シンボリックリンク封じ) | グリルQ4 |
| R8 | メールはアプリ内の1グループ。未返信スレッドをトークルーム風に一覧し、スレッド全文を読める (bot の mail-snapshot.json convo 流用) | グリルQ2 モック選択 |
| R9 | クイック返信: 1行方向づけ (空でも可) → タップ → **即時に単発 Claude が起動**して宮崎さんの文体 (client-mail-standards + check_mail.py) で起草 → `create_draft` (in_reply_to 付き) で Gmail 下書きへ → アプリに「下書き済」バッジ。**送信は一切しない** — 送信は宮崎さんが Gmail 公式で押す | グリルQ5 + mail-monitor-design R11 |
| R10 | 見た目: iPhone ネイティブ感・遷移がヌルヌル・PWA (ホーム画面追加・1 URL)。名称 = **ポケットmycmux**、URL = `/pocket/` | グリルQ6 |

## Phase 分割と受け入れ基準

| Phase | 内容 | 受け入れ基準 |
|-------|------|-------------|
| P0 | 配信骨格 (`/pocket/`・トークンレス) + グループ一覧 + タブ一覧 (read-only) | iPhone で開きタブ一覧が実物と一致 |
| P1 | ペイン詳細の型付きタイムライン | 走行中セッションの直近やり取りが LINE 風に読める |
| P2 | コンポーザ (idle 即送 / 稼働中は予約投函 / 画面 read 送達確認) | iPhone からの指示が着弾し送達確認が画面根拠で出る。予約分が idle 化後に自動投函される |
| P3 | パスリンク → ファイルビューア (HTML/MD/docx→PDF・許可2ルート+拒否リスト) | タイムライン中のパスをタップして中身が読める。拒否リスト対象が 403 になる |
| P4 | メールグループ (一覧・全文・1行→即時起草→Gmail 下書き・下書き済バッジ) | 「よろー」→数分後に Gmail に下書きが実在。送信は発生しない |
| P5 | 磨き (PWA manifest・遷移・未読/要対応バッジ・SSE 検討) | ホーム画面 1 タップ・ネイティブ感 |

## セキュリティ境界

- tailnet 内限定。Funnel 禁止。ループバック bind + `tailscale serve` proxy (ハブ P1 と同型)
- ファイル配信は許可2ルート + 拒否リスト (機密パターン) + シンボリックリンク封じ + パストラバーサル対策
- 起草ジョブは mail-monitor 設計書の安全境界に従う (prompt injection 対策・ツール範囲限定・**送信操作は実装しない**)
- G: 配信は DriveFS 重負荷時に詰まる実測あり → タイムアウトを短く切り「あとで再試行」を出す

## 用語 (P0 で新 repo の CONTEXT.md に転記する)

- **ポケットmycmux**: 本アプリの正式名。URL パスは `/pocket/`
- **グループ**: トップ画面の大分類 (mycmux / メール / レポート棚)。mycmux グループの中身 = タブ一覧
- **トーク**: タブ1個に対応する行およびその詳細画面
- **予約投函**: 稼働中ペイン宛の指示を PC 側が保持し、idle 化を検知して自動送信+送達確認する仕組み
- **下書き済バッジ**: Gmail スレッドに DRAFT が存在することを示す表示 (bot の has_draft 検出を流用)
