# サイドバーのキャラ (pet)

現行仕様: 2026-10-09。日本語は **ワークスペース > タブ > ペイン** ([ADR 0013](../../adr/0013-vocabulary-workspace-tab-pane.md))。
元の設計と D0〜D9 / 監査裁定は [2026-09-10 の計画](../../plans/2026-09-10-pet-state-design.md)、hook の意味は [ADR 0012](../../adr/0012-hook-attention-semantics.md)。

キャラはワークスペース内の全タブ・全ペインをまとめて、「人に何をしてほしいか」を示す。
表示の既定は **キャラなし**。設定 → キャラ → ワークスペースに1体、で表示する。
応答ターンの終了は、依頼全体の完遂を保証しない。

## 5 つの状態

| 状態 | 意味 | アトラスの行 | 周期 |
|---|---|---|---|
| 呼んでる / calling | 質問・承認・送信前の入力で、人の操作が要る | 6 | 1010ms |
| 困ってる / stuck | エラー・レート制限で、人の処置が要る | 5 | 1220ms |
| 走ってる / working | 作業の合図がある | 7 | 820ms |
| 見て見て / ready | 応答ターンが終わり、まだ見ていない | 8 | 1030ms |
| 寝てる / resting | 上の合図がない、または停滞・既読の応答 | 0 | 6600ms |

8 列・9〜11 行の Codex 規格のアトラスを使う。同梱 Clawd と有効な外部候補が対象。
状態が続く間は、表示中のワークスペースかどうかによらず再生する。
動きを減らす OS 設定 (`prefers-reduced-motion`) では選択行のコマ 0 に固定する。
描画は既存の事前縮小・縁の色の除去・compositor のコマ送りを維持する。

## 分類表 (実行順)

`classifyPetTier` は上から最初に一致した状態を返す。
入力は全セッションに届く状態フィードの attention / activity / 最終出力時刻、停滞の理由、既読、観測集合。
画面の waiting / spinner / outputActive は、そのペインの端末がマウントされている間だけ信頼する。
`uiState` と `processIsShell` 単独で作業を推定しない。

| 行 | 条件 | 結果 |
|---|---|---|
| R0 | 種別が web / browser / online | 寝てる |
| R1 | 観測中で画面が waiting | 呼んでる |
| R2 | 観測していないペインで attention が input / approval | 呼んでる (既読でも続く) |
| R3 | attention が rate_limited / error | 困ってる (既読でも続く) |
| R4 | stall が queued_input | 呼んでる |
| R7 (監査裁定) | 観測中で画面の spinner がある | 走ってる。古い done / stall より先 |
| R5 | attention が done | 未読なら見て見て、既読なら寝てる。空の prompt の再描画で走らない |
| 再開 (監査裁定) | attention が none / 未指定、解除時刻から 15 秒以内、activity が idle 以外 | 走ってる。解除前の停滞より先 |
| R6 | stall が no_output / silent / pty_dead | 寝てる |
| R8 | **観測中**の outputActive、または backend 最終出力から 15 秒以内 | 走ってる |
| R9 | activity が running_silent | 走ってる。出力のない長い処理にも適用 |
| R10 | その他 | 寝てる |

背景で凍った outputActive が行 7 を残す不具合を、R8 の観測条件で修正した。
無出力を停止の証明に格上げしない。停滞自体は既存のプロセス・画面の意味変化を調べる判定が持つ。

## 集約と切替

優先は **呼んでる > 困ってる > 走ってる > 見て見て > 寝てる**。
1 本でも人待ちなら呼んでる。作業中と未読の応答が並ぶなら走ってる。ペイン 0 本なら寝てる。
警告の未読リングは input / approval / error / rate_limited のみを数える。done は含めない。
したがって作業中と未読 done の集約では、キャラと警告リングだけから未読 done を知ることはできない。

| 切替 | 保持 |
|---|---|
| どこからでも calling / stuck へ | 即時 |
| working → resting / ready | 3 秒 |
| resting / ready → working | 即時 |
| calling / stuck → 下の状態 | 即時 |
| ready → resting (既読) | 即時 |

再開や人待ちが来たら pending の保持を取り消す。unmount 時にも timer を破棄する。
15 秒の共有時計で出力期限を調べるため、出力から停止表示まで最長約 30 秒 + 保持 3 秒になる場合がある。
attention / activity が変わった場合は feed の更新で先に反映する。

## 新しいワークスペースへの割当

既定の `petNewWorkspaceMode="random"` は **使用中を避けるランダム**。
候補は同梱 + 読込が確認できた外部キャラのうち、設定で有効にしたもの。
まず使用中でない ID を袋の残りからランダムに引く。全候補が使用中なら袋の残りから引き、袋を使い切ったら全候補を戻す。
候補が 1 体なら重なる。手動選択・fixed・choose の後から選んだものも使用中として数える。

- 有効な保存済み割当は維持し、起動で一斉に引き直さない。明示的な未割当もそのまま復元する。
- ワークスペースの削除・手動変更で最後の利用がなくなった ID は袋に戻す。同じ ID を別のワークスペースが使っていれば返さない。
- チェックを外すと新しい抽選から除外する。既存の割当は変えない。再び有効にした候補や新しく追加した候補は袋に入る。最低 1 候補は残す。
- 外部ファイルの削除・隔離・規格外で候補から消えた ID は、成功した再スキャンで確認して代替を引く。存在するほかの割当は維持する。scan が失敗したときや未読込の同梱だけの一覧では欠損扱いにしない。
- 表示 off では外部アトラスを読まない。保存された候補 ID の控えがあれば、その有効な ID を抽選に使う。まだ外部を読み込んだことがない状態では同梱だけが候補。
- 「振り直す」は、今の ID 以外の使用されていない候補を優先する。ほかに候補がない場合は同じものを許す。
- ペインの再配置では group ごとに別の割当を計画する。プレビューを開いただけでは袋を消費せず、適用時だけ記録する。

使用中は今のウィンドウのワークスペース集合で数える。別ウィンドウからの同時作成について原子的な全体の重複回避は保証しない。

## 保存・復元

`data.json` の各ワークスペースの既存 `pet` に ID、設定の `pet_random_bag` に次の状態を保存する。

```json
{
  "version": 1,
  "candidates": ["clawd", "external:sample"],
  "remaining": ["external:sample"]
}
```

候補順は ID の整列で安定させ、乱数を引数に注入して試験で再現する。保存するのは候補 ID と袋の残りで、アトラスやセッション状態ではない。
袋は省略可能。古い data.json、未知版、壊れた袋では現在の候補と使用中の割当から再構成できる。
保存済みワークスペースの復元・ウィンドウ間の採用では抽選し直さず、保存済み袋を再消費しない。
leader と child の両方の設定読込で復元し、既存の設定保存と dirty 購読で永続化する。保存形式の版と新しい依存は増やさない。
古い catalog 要求の応答は、後から確認した catalog を上書きしない。

## 設定と戻し方

| 設定 | 値・既定 | 意味 |
|---|---|---|
| 表示 (`petDisplayMode`) | none **既定** / ws、保存互換の both | キャラなし / ワークスペースに1体。both の追加 UI は未実装で非表示 |
| 作成 (`petNewWorkspaceMode`) | random **既定** | 使用中を避けるランダム |
| 同上 | random-repeat | 重なってもよい以前のランダム |
| 同上 | fixed | 設定した 1 体。使えない ID は有効な先頭候補 |
| 同上 | choose (保存互換) | 作成時は未割当。毎回選ぶ作成 UI は未実装で非表示 |
| 候補 (`petDisabled`) | [] **既定** | 抽選から除く ID。既存割当は保持 |

以前の抽選へ戻すには、設定 → キャラ → 新しいワークスペースを作ったとき →
**「候補からランダム (重なってもよい・以前の方式)」**を選ぶ。これは既存の割当を変えない。
表示の既定や状態の優先・周期・保持の数値は今回変更していない。

## 確認範囲と課題

`petStateTable.test.ts` が R0〜R10 の feed と既読の入力、既存 `petState.test.ts` が全 25 集約と保持、
`petSidebarFeed.test.tsx` が実 sidebar の合成 feed、`petSprite.test.ts` が行・周期・reduced-motion を確認する。
`petAssignment.test.ts` / `petWorkspaceAssignment.test.ts` が袋・復元・削除・追加・欠損・preview、設定試験と契約試験が既定・戻し方・保存境界を確認する。

hook のない席の人待ちや prompt 再描画、CLI 製品ごとの実際の連携、画面の見え方は合成 feed の試験だけでは証明できない。
元の計画の S1〜S9 を隔離した Windows 試験機で確認する。
状態の根拠・連携の観測状況の表示、未読 done の印、複数ウィンドウの共通割当は、採否を決めてから別の変更で扱う。
