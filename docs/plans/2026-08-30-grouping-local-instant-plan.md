# タブ再配置 ローカル即時案 (便C) 設計

状態: 実装中 (2026-08-30)。前提 = v0.60.1 で判定 effort 固定と参考表示は入った。
残る遅さ = **キャッシュが無い初回の 100 秒待ち**。これは判定モデルの生成時間そのもので、
effort では縮まない。よって「LLM を待たずに出す案」を足す。

## 1. 何を作るか

パネルを開いた瞬間に、**IPC ゼロ・LLM ゼロ**で作れる決定的な再配置案を1件出す。
AI の案が出来たら差し替える。ユーザーが即時案を編集していたら差し替えない。

即時案は参考表示ではなく**そのまま適用できる本物の案**にする。これが「サクサク」の本体で、
待てる人だけが AI の案を待つ、という形にする。

## 2. 入力 (ここが速さの理由)

現行の走査は ①PTY メタ 1回 ②出力時刻 1回 ③**タブ本数ぶんの画面末尾読み** (19タブ = 19往復) を
待つ。即時案はどれも使わない。使うのは Zustand ストアだけ:

- `useWorkspaceListStore` … ワークスペース・ペイン・タブ・列構成
- `usePaneMetadataStore` … cwd・エージェント種別
- `useSessionAttentionStore` … 要対応 (error) の判定

画面末尾テキストは使わない (grouping では末尾を表示に使っていないことを確認済み)。
`GroupingScan` の `tail` は空配列で埋める。

## 3. クラスタリング (決定的・ヒューリスティック辞書なし)

1. **系譜**: `origin.parentTabId` で union-find。親子は必ず同じグループ
2. **案件 = cwd のトライ切り**: 全タブの cwd をセグメント列にしてトライに入れ、各タブについて
   「自分の経路上で、配下のタブ数が2以上ある最も深いノード」をグループキーにする。
   同じ案件フォルダ配下は自然に1つへ集まり、単独のタブは共通の親 (ホーム等) へ落ちる。
   閾値も辞書も持たないので、環境が変わっても壊れない
3. **要対応の隔離**: attention が `error` のタブは案件より優先して 「要対応」 グループへ分ける
   (v3 の配置ルールと同じ思想)
4. **命名**: グループキーの末尾セグメントを日本語名規則 (`isJapaneseGroupingName`) に通るよう
   整形 (`_ - .` を除去・20文字で切る・一般英単語なら連番名へ退避)。既存ワークスペース名と
   衝突する場合も退避する

## 4. レイアウト (v3 の配置ルールをそのまま機械化)

- **列で分ける**。1列1ペイン。行は増やさない
- タブが列の上限 (4) を超えたら、**裏タブに重ねる** (`pane.tabIds` を複数にする)
- 親 (系譜の根・エージェント無し) をその列の先頭ペインに置き、子は同じペインの裏タブへ
- グループのタブが今すでに1つのワークスペースに収まっていて、そのワークスペースが
  他のタブを含まないなら `disposition=keep` (動かさない)。それ以外は新規ワークスペースへ

## 5. 出す・差し替える

- パネルを開いたとき `peek()` が `miss` / `hard-stale` / `pending` なら、即時案を作って
  その場で表示 (`freshness = "local"`)。同時に前面判定を走らせる (既存の keepCurrent 経路)
- AI の案が届いたとき、**ユーザーが編集していない (compare モードのまま・編集セッションが
  clean)** なら差し替える。編集していたら差し替えず、状況行で知らせるだけにする
- 即時案が作れない (タブが少ない・検証に落ちる) ときは従来どおり空白+判定待ち

## 6. 安全弁

- 生成した案は `validateEditedPlan` に通し、1件でもエラーが出たら **null を返して従来動作へ**。
  壊れた案を見せない
- 適用経路は既存のまま (`prepare` → `commit`)。即時案でも stale 判定・ロールバックは同じ
- PTY・セッションには一切触れない
