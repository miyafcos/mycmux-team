# ailog 系列色の設計契約

AIログ分析 (ailog) の使用量ダッシュボードで、モデルの系列色をどう決めるかの正本。
実装は `src/components/ailog/modelColors.ts`、色空間の変換は `src/lib/oklch.ts`、
契約テストは `tests/unit/ailogPalette.test.ts`。

## 原則

**色相 = 会社、明度 = ティア。上位ティアほど濃い。**

色は**モデル名だけで決まる純関数**であること。期間・指標・並び順・使用量に依存してはいけない。
以前は「期間合計の降順ランクでパレットのスロットを配る」方式だったため、期間を切り替えると同じ
モデルの色が変わっていた。これを構造的に禁止する。

テーマ変数 (`var(--cmux-*)`) は使わない。多数の系列を同時に判別する必要があり、ライト・ダーク
両方で読める固定色相を選ぶ必要があるため。系列色は**塗り (fill) 専用**で、文字色には使わない
(文字は常にテーマの前景色)。

## 色相

OKLCH の色相角で定義する。ブランド由来の HSL 色相とは値が違うので注意すること。

| 会社 | 色 | OKLCH h | 参考 |
|---|---|---|---|
| Anthropic | コーラル | 39 | `#D97757` = HSL 14.8 / OKLCH 38.8 |
| OpenAI | ブルー | 258 | `#5e9eff` (エージェント種別の Codex 色) = OKLCH 258.5 |
| xAI | マゼンタ | 335 | |
| Google | ティール | 170 | 実データはまだ無い (後述) |

4色相はおよそ 80° 間隔で散っている。

OpenAI がブルーなのは、サイドバーで見慣れた Codex の色に揃えるため。**xAI がバイオレット (296)
ではなくマゼンタなのは、バイオレットがこのブルーから 46° しか離れず、1型で ΔE 0.019、2型で
0.023 まで潰れる (床 0.025 を割る) ため。** Google は OpenAI が明け渡したティールに入っている。

ローカル (ollama) / 定額 (fugu) / 会社不明 / 下位まとめは色相を持たず、`NEUTRAL_COLOR`
(`#8c8c8c`) で描く。**彩度ゼロは意図的** — 「どの会社でもない」色なので、どれかの色相の淡い
一員に見えてはいけない。以前の `#8a8f9c` は青に寄っていたため、OpenAI がブルーになった時点で
その muted 段と ΔE 0.036 まで接近した。

## 明度の安全帯 — L = [0.500, 0.656]

この帯域は好みではなく実測による制約である。

- 白 (`#ffffff`、ライトテーマの最明 surface) に対しコントラスト 3:1 を満たすには **L ≲ 0.66**
- `#070809` (最暗テーマの surface) に対し 3:1 を満たすには **L ≳ 0.49**

**ライト・ダーク両対応の安全帯は幅 0.156 しかない。** ティア段はこの帯域を等分するので、
隣接段の ΔE 0.035 を守れるのは **1社あたり 5段まで**。これが `TIER_LADDER` の段数上限の根拠。

段を増やしたくなったら、新しい段を足さずに既存段の muted に寄せること。色相シフトやハッシュに
よる微差は採用しない — 実測で ΔE が 0.018〜0 まで潰れ、識別に寄与しないことを確認済み。

## ティアと世代

段は `TIER_LADDER` にハードコードする。名前からの自動推定はしない。

```
anthropic: fable-5 > opus-5 > sonnet-5 > haiku-4.5          (4段)
openai:    gpt-5.6-sol > gpt-5.6-terra > gpt-5.6-luna
           > gpt-5.5 > gpt-5.4                               (5段)
xai:       grok-4.6                                          (1段)
```

同じティアの旧世代 (`opus-4.8` など) は段を増やさず、`LEGACY_FAMILIES` で親段に紐づけて
**その段の muted 色**にする。muted は L と h を据え置き、ガマット clamp **後**の彩度に 0.55 を
掛けて作る (clamp 前に掛けると彩度が伸びない色相で差が潰れる)。

`model` 軸では variant が畳まれた display family (`gpt-5.6`) が届く。ティアが確定しないので
`FAMILY_REPRESENTATIVE` で代表段に解決する。**未登録扱いにはしない** (ハッチを出さない)。

## 辞書に無いモデル

- **会社が判明する場合**: その会社の最淡段の muted + 斜線ハッチ。辞書の更新が必要だと見て分かる
- **会社も不明**: `NEUTRAL_COLOR`

切替点は `UNTIERED_POLICY` の1定数。

ハッチは **45°の実線**。破線は使わない — `UsageBucketChart` が高さ 1px のバーを描くため、破線だと
潰れて見えなくなる。SVG は `<pattern>` を `url(#ailog-hatch-<hex>)` で参照し、HTML のスウォッチは
CSS の `repeating-linear-gradient` で同じ見た目を作る (CSS から SVG pattern は参照できない)。

## 軸ごとの割当

色相が意味を持つのは6軸のうち3軸だけ。

| 軸 | 割当 |
|---|---|
| `model_raw` / `model` | 会社色相 × ティア明度 |
| `provider` | その会社の**帯域中央** (L=0.578) の solid |
| `kind` | `src/lib/agentKindColors.ts` を再利用 (サイドバーの CLI 色と一致させる) |
| `project` / `effort` / `origin` | 名前ハッシュの8色リング。順位ではなく名前で決まる |

会社軸に最淡段を使ってはいけない。その会社の最下位モデル (haiku / gpt-5.4) と同色になり、
かつ段数の違う会社どうしで明度が揃わなくなる。

## 識別性の実測

同時に並ぶ10系列 (Anthropic 4 + OpenAI 5 + xAI 1) のペアワイズ最小 OKLab ΔE:

| 視覚 | 最小 ΔE | 最悪ペア |
|---|---|---|
| 正常 | 0.041 | gpt-5.5 vs gpt-5.4 |
| 1型 (protan) | 0.038 | gpt-5.5 vs gpt-5.4 |
| 2型 (deutan) | 0.041 | gpt-5.6-sol vs gpt-5.6-terra |
| 3型 (tritan) | 0.035 | gpt-5.6-sol vs gpt-5.6-terra |

最悪ペアが**すべて同一会社の隣接段**になっている。会社どうしの分離は十分に取れていて、残る制約は
段の刻みの細かさだけ、という状態。これも段数上限5の裏付けになっている。

### 既知の限界

**OpenAI (258) と Google (170) は3型で ΔE 0.015** まで接近する。ΔE 床のテストは
core-3 (Anthropic / OpenAI / xAI) にのみ課しており、Google は含めない。

これは `gemini-*` が `DEFAULT_PRICES` にも `FAMILY_STEMS` にも存在せず、実データに現れないため。
Antigravity (`agy`) のログには**トークン usage が記録されていない** (`~/.gemini/antigravity-cli/`
の transcript.jsonl にトップレベルキーとして `usage` も `*_tokens` も無い) ので、ailog は現在
Gemini の使用量を集計できない。Google の色相枠は将来の取り込みに備えた定義にとどまる。

**Gemini を実際に集計できるようになったら、この節の限界を解消すること。** 4社が 80° 間隔で
埋まっているので、Google をどこかへ動かすには他社も一緒に動かすことになる。5社目を足すときも同じ。
そのときは色相の再配置を全社まとめて計算し直し、core を4社に広げて床を課すこと。

## 契約テスト

`tests/unit/ailogPalette.test.ts` が以下を機械検証する。パレットを触るときはここが落ちないこと。

- **コントラスト床**: 全 solid / muted が `themeDefinitions.ts` から動的に抽出した最明・最暗
  surface の両方に対し 3:1 以上。テーマが増えても自動で追随する
- **色相の一致**: 同一会社の全色の OKLCH 色相差が 0.5°未満 (ガマット clamp は彩度しか動かさない)
- **明度の単調性**: 各社のティア順に L が厳格に増加する。**彩度の単調性はアサートしない** —
  ティール色相は低 L で sRGB ガマットに当たるため実測で非単調になる
- **隣接段の ΔE** 0.035 以上、**10系列のペアワイズ ΔE** (色覚シミュレーション込み)
- **実測 hex 表との一致** (回帰検知。丸め差 1〜2 LSB は許容)
- **`price.rs` との parity**: `DEFAULT_PRICES` の全モデルが段を持つこと、`FAMILY_STEMS` の全 family が
  段か `LEGACY_FAMILIES` に載っていること、`ModelProvider::as_str()` の全 provider が色相を持つか
  `HUELESS_PROVIDERS` に載っていること。**Rust に新しい会社やモデルを足したときに落ちる**
- **順位非依存**: 同じモデルを総量1位にした入力と最下位にした入力で色が一致すること

`price.rs` に新しいモデルや `ModelProvider` を足すと parity テストが落ちる。落ちたら
`TIER_LADDER` / `LEGACY_FAMILIES` / `PROVIDER_HUE` のどれかを更新すること。テストを緩めて
通してはいけない — 色が付かないモデルが黙って増えるのを防ぐための仕掛けである。
